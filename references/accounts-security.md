# 多账号 + 项目授权 + 安全模式

## 两级角色

- 种子账号(见仓库 `config.json` 的 `credentials`,首次启动 users 表为空时写入)= **superadmin**(见全部项目)
- 超管创建的账号 = **user**(成员,仅见被分配的项目);老库迁移自动把存量用户升级为超管

**信任模型**:只隔离项目可见性 —— 普通用户的项目列表被过滤、项目级 API 未分配 → 403;**其余功能全部照常**(终端/tmux、SQL 查询与审批、备份、nginx、系统资源、review-mode)。

**超管专属**:① 用户管理 API/界面 ② 项目注册表增删改(＋添加项目/编辑/移除/用户管理按钮仅超管可见,后端强制)。

**role 实时生效**:JWT 里的 role 只是登录快照(供 UI);后端每请求实时查库 —— 超管改分配/删用户立即生效(被删用户 token 立即 401)。

用户管理界面:⚙ → 账号 Tab(仅超管):左用户列表 / 右详情 —— 勾选即保存的项目分配、重置密码、删除账号(不能删自己)、＋添加用户(用户名 `[A-Za-z0-9_-]{2,32}`、初始密码 ≥4 位)。

## 安全模式(隐身/防探测,⚙ → 安全 Tab)

- **开启后**:未解锁的访问 —— 页面、静态资源、全部 API(连 `/api/auth/login`)—— 一律返回与 Express 默认无差别的 404,扫描器探测不到服务存在;WebSocket 终端升级同样直接断开。
- **例外**:本机 ai-token 直通(`cp` 脚本不受影响)—— 持有 0600 token 文件 = 本机主人;外网探测者没有 token,看到的依旧全 404。
- **解锁**:在任意入口(localhost:3008 / nginx 域名 / FRP 端口)后拼**秘密路径**访问一次 → 种 `cp_gate` HttpOnly cookie(90 天)→ 302 /login,该浏览器此后正常。路径是唯一秘密,与入口域名无关。
- **管理**(⚙ → 安全):开关、查看/复制路径、自定义路径(`/` 开头仅 `[A-Za-z0-9_-]` 长 8~128,不能 `/api` `/assets` `/favicon` 开头)、⟳ 随机重生成(旧路径立即失效)、🚪 吊销所有已解锁浏览器(当前浏览器自动续上)。
- 配置存全局 settings 表 key=`security`(`{enabled,secretPath,cookieSecret}`),重启仍生效;开关/操作时自动给当前浏览器种 cookie(不会把自己锁外面)。
- ⚠ **忘记秘密路径**:只能本机查 `~/.code-panel/data.db` 的 settings 表(CODE_PANEL_HOME 覆盖时查对应目录)。

## 本机免密通道(ai-token)机制

- `~/.code-panel/ai-token`:启动时自动生成,128bit,chmod 600,**永不进 git**
- 语义:能读该文件的进程 = 本机用户 = 面板主人 → 以超管身份直通全部 API(含安全模式),**不依赖账号体系**(改密/删号不影响)
- 调用方一律用仓库根的 `cp` 脚本,不直接摸 token
- ⛔ ai-token 通道对 SQL 审批/评审模式端点 403(审批必须人肉在 /sql 页操作)
- **吊销/轮换**:删除文件 → 重启面板 → 重新生成
- 远程机器没有这个文件 → 远程调用照常走登录,天然「只有本机免密」
