# design-prd — 需求中心目录化工具(通用版,由 code-panel 初始化)

> 本 skill 骨架由 code-panel 内置模板生成(`templates/design-prd/`),所有项目调用方法一致;
> 项目特有的规范(平台/端口/表规约等)写进 `.code-panel/prd/原型规范/`,与本 skill 共存互不覆盖。
> skill 升级 = code-panel 仓更新模板后重跑初始化(已有文件不覆盖,见「初始化」节)。

## 需求中心(唯一事实源)

**开发需求/计划/伪代码/原型 HTML 一律写 `<项目根>/.code-panel/prd/<人名>/`**,人名目录 = 各人需求中心:

```
.code-panel/prd/
├── <人名>/                     ← 每人一个中心(看板标题 = 目录名)
│   ├── index.md               ← 看板:程序整份渲染,禁手改
│   ├── notes.md               ← 手写区(AI 总结/里程碑),生成器永不覆盖
│   ├── specs → ../../../specs ← 软链(初始化时自动建;spec 渲染才有返回按钮)
│   └── plan/
│       ├── todo/  doing/  done/          ← 状态 = 目录位置,mv 即流转
│       ├── plan-NN-<名>.md               ← 计划文档(五段式)
│       ├── plan-NN-伪代码/               ← 步骤书目录(见渲染契约)
│       └── plan-NN-<页面名>.html          ← 原型(与伪代码目录同层)
└── 原型规范/                   ← 项目自己的写作规范(CONSTITUTION/TEMPLATE,可选)
```

计划编号各中心独立(plan-01 起);跨中心协作靠仓库根 `specs/` 全团队共用防撞号。

## md-render 渲染契约(code-panel /api/prd/view,违反 = 渲染不出来)

1. 步骤 md 命名 `步骤N-名称.md`(1→N 连续),放 `plan/plan-NN-伪代码/`
2. **代码文件必须放伪代码目录内 `伪代码/` 子目录**,命名 `步骤N-<端>-<功能>.<ext>`;步骤 md 正文一行 `> @tabs 步骤N` → Tab 切换组件(代码高亮 + ⛶ 全屏)。平铺在根/用 `01-` 数字前缀 = 匹配不上不渲染
3. **原型图引用用反引号路径**:`> 原型图：` + 反引号包 `../plan-NN-页面名.html` → 自动 iframe 内嵌;md 链接式 `[x](y)` 只变普通链接不内嵌
4. 左栏只列当前目录 md;用户预期 = 点步骤 md 一页看全(原型 iframe + 代码 Tab)
5. 步骤 md 四件套顺序:`## 1 介绍`(含原型图)→ `## 2 表结构` → `## 3 流程`(文字步骤)→ `## 4 伪代码 Tab`(@tabs)
6. 原型 HTML 自包含(内联 CSS,类名 `proto-*` 前缀);前端开发以原型为最高依据 1:1 还原

## 看板 = 程序渲染(code-panel 内置生成器)

index.md **整份由程序输出,禁手改**;列 = 计划 | 内容 | 伪代码 | spec | 评审 | 状态。

计划文档锚点(生成器解析,格式勿改):
- `> 主题: <一句话>` → 内容列(超 120 字截断;缺省取「一、目标一句话」首行)
- `> spec 访问:[specs/{目录}](/demo-v2-specs/{目录}/)` 可多行 → spec 列(spec①②③,跳规格化目录)
- `## 评审` 章节,条目 `- YYYY-MM-DD 姓名: 意见` → 评审列(最新一条前 50 字)
- `> 归档: YYYY-MM-DD` → done 状态列

### 🚨 重绘铁律(写完必做,自动执行不问不省)

`.code-panel/prd/` 下任何变更 —— 计划文档/伪代码/原型/spec 回写/评审追加/归档 mv —— 写完**立刻重绘**:

```bash
# 本机免密(cp 调用器在 code-panel 仓根,自动带 ai-token;项目 id 用 cp get /api/projects 查)
<code-panel仓根>/cp post /api/prd/gen-board -d '{"project":"<id>"}'
```

面板没跑时 → 请用户在面板 PRD 页点 **↻ Refresh**(同一路由)。

## spec 规范(speckit)

- **目录带用户名前缀**:`specs/{人名}-{计划编号}-{短名}/`(仓库根 specs/,全团队共用防撞号)
- spec.md 必含**原型索引表**(原型完整路径 ↔ US/task);UI task 内嵌「原型还原点」清单
- 规格化完成**回写计划文档** `> spec 访问:` 行(见上),然后重绘看板(spec 列亮起)
- 中心内软链:`ln -s ../../../specs <中心>/specs`(已存在则跳过)

## 指令集

| 指令 | 触发词 | 动作 |
|---|---|---|
| **计划** | "写计划/立项 plan-NN" | 读原型规范(如有)→ 写计划文档(目标一句话/待决既定/任务拆解/风险/关系,含 `> 主题:`)→ 重绘 |
| **伪代码** | "写伪代码" | 按计划任务拆解写 `plan-NN-伪代码/`(index.md 入口 + 步骤 md 四件套 + 伪代码/ 代码文件 + 原型 HTML)→ 重绘 |
| **检查** | "检查伪代码" | 步骤衔接/原型图充分且可内联/四件套/@tabs 文件存在/建表 SQL/前后端代码/菜单清单/index 入口,✅❌ 报告,❌ 当场补写 → 重绘 |
| **定稿** | "plan-NN 定稿" | 用户过目认可 → 计划文档加 `· 定稿: YYYY-MM-DD` → 重绘 |
| **spec** | "plan-NN 生成spec" | speckit 规格化(specify→plan→tasks,不 implement;原型索引表 + 还原点)→ 回写 spec 访问行 → 重绘 |
| **归档** | "完成了/归档" | 补 AI 总结/完成描述 → mv `plan/done/` + `> 归档: 日期` → 重绘 |
| **刷新** | "刷新/重绘看板" | 调 gen-board 重绘全部中心(见重绘铁律) |
| **查看** | "看板/进度" | 读各中心 index.md / ls 目录 |

## 初始化(本项目首次)

- 面板 PRD 页空状态点「初始化 design-prd skill」,或 `cp post /api/prd/init-skill -d '{"project":"<id>"}'`
- 幂等:已存在的文件**永不覆盖**(项目定制不会被冲掉);补建 `<项目根>/.code-panel/prd/` 目录与 specs 软链
